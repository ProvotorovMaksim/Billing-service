# Технический обзор · Billing Service — тарифы, подписки и платежи

Оценка для позиции Junior Python Developer / Integration Engineer. Основание — статический анализ исходников, сохранённых в Git на коммите `7059087`. Выводы о сценариях отказа требуют проверки в рабочем окружении.

## Сильные стороны

Тарифы, платежи и подписки разделены по назначению. Внешний SDK вынесен из HTTP-роутера.

## Слабые стороны и архитектурные замечания

Платёж записывается в БД в несколько этапов вокруг вызова ЮKassa. Сбой между успешным вызовом и сохранением внешнего ID требует сверки. Синхронный SDK и Kafka flush в async-потоке требуют оценки блокировок.

## Что проверить на демонстрации

Нужны проверка происхождения и идемпотентность webhook, согласование Kafka-топика с получателями и проверка ошибок SDK.

## Вопросы для технического интервью

1. Что случится при двойной доставке webhook?
2. Как доказать, что сумма получена из правильного тарифа?
3. Как восстановить платёж после падения между внешним запросом и commit?
